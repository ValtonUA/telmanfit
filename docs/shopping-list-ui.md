# T5.7a — екран списку покупок (Draft PR)

## Контекст і межі

T5.3 уже реалізував read-only агрегатор `GET /api/meal-plan/shopping-list?week=N` із exact assigned published versions, захистом ClientSession/owner, fail-closed 409 та decimal-рядками без float. T5.7a — **лише клієнтський React UI** над ним. У scope немає нових таблиць, Laravel API, business rules, конверсій, пагінації, збережених чекбоксів, SKU, закупівельного округлення, власних категорій чи кухонних сесій. Production OFF.

FEASIBILITY: PASS — наявні API, React SPA fallback, чотири вкладки й прямий `/app/meal-plan`, синтетичні PG/Chromium fixture/runner та повний контракт T5.3. Жодних реальних клієнтських записів чи зовнішніх сервісів не потрібно.

## Навігація та дані

- **Вкладка «Раціон»**: видиме посилання «Список покупок на тиждень» з фактично вибраним `week`, без зміни 4-tab навігації.
- **Сторінка** `/app/meal-plan/shopping-list?week=N`, пряма адреса та reload; повернення на `/app/meal-plan?week=N`. Відсутній `week` використовує поточний авторський тиждень на сервері, а не обчислений у браузері.
- Селектор тижнів береться **тільки** з `response.weeks`, з календарними датами T5.3. Не створюємо цикли меню, тижні поза призначенням, покупок на неіснуючі дні.
- `ready`: перелік з точними `ingredient_id`, `name`, `quantity_grams` і `quantity_grams_exact`; з `source_quantities` для довідкового перегляду UOM. Ніякої арифметики або округлення у React. Суто візуально видаляються хвостові нулі з фіксованого шестизнакового decimal.
- Категорії **не відображаються**: T5.3 не містить category поля. Не виводимо їх за назвою й не змінюємо API поза погодженим scope.
- Пояснення: харчова потреба — не кількість магазинних упаковок. `source_quantities` не видавати за рекомендації щодо купівлі штук/банок. Несумісні UOM/фактори не зливаються клієнтом.

## Стани й безпека

- `no_assignment`: явне повідомлення без вигаданих продуктів; `week_unavailable`: повідомлення й інший тиждень; `ready + items=[]`: чесний порожній список.
- HTTP 409 (`shopping_list_unavailable`): жодного часткового результату, повідомлення звернутися до тренера. 401/revocation: скидання приватних даних і повернення до login; 422/503/network: помилка й retry, без показу stale results.
- URL `week` обмежено позитивним цілим до 2147483647. Перезавантаження, visibility/focus/60s refresh із захистом від запізнілих відповідей: немає показу старого призначення на зміненій сесії.
- Усі дані — API JSON через чинний `api.ts`, `no-store, private`; не використовуємо localStorage і не створюємо нові write endpoints чи авторизаційні винятки.
- UX: 1440/390/320, light/dark, довгі назви, семантичні headings/list/select/details, keyboard focus, жодного горизонтального скролу.

## Приймання

На ізольованому PostgreSQL 18 із синтетичним T5.2 fixture/real AUTH-4/5 ClientSession браузерний runner перевіряє: реальне значення API, точні грами, selector week=1→2, пряму адресу/reload, повернення, 409 без stale list, retry, responsive light/dark 1440/390/320. Backend T5.3 security/read-only тест лишається без змін і входить у штатний regression. Обов'язкові Fast/Docs/Targeted на фінальному SHA PR. Цей опис не підтверджує production-готовності та не дозволяє жодних змін робочої БД.

Наступне T5.7b — кухонні сесії та мегарецепти: data contract/версіонування/безпека приготування потребують окремого погодження.
