# UX-4 — компактний редактор дня

## Обсяг

- День і каталог доступні одночасно; desktop-панелі прокручуються незалежно.
- Каталог має сітку 3/2/1 колонки на широкій/середній/мобільній ширині.
- Селектор цільового прийому і кнопка картки відкривають штатне підтвердження додавання; мобільний шлях працює touch і клавіатурою.
- Перехід до огляду тижня лишається доступним із редактора дня. Дії публікації, повторення й керування тижнем розташовані в огляді.
- Stage 4 writer, бізнес-правила, схема, опубліковані версії, історія та авторизація не змінювалися.

## Browser acceptance

`DAY_BROWSER_ONLY=1 bash tests/pg/run-stage1.sh` пройшов на Chromium із новою
ізольованою PostgreSQL 18.6 базою, без повторного запуску PG/concurrency наборів.
Усі сценарії завершили шлях «тиждень → день → пошук у довгому каталозі → додавання
до обраного прийому → тиждень»:

| Viewport | Light | Dark | Ввід |
|---:|---|---|---|
| 1440 px | PASS | PASS | mouse, клавіатура |
| 390 px | PASS | PASS | touch |
| 320 px | PASS | PASS | клавіатура |

На 1440 px також підтверджені три колонки, незалежне колесо прокрутки обох панелей
і відсутність прокручування сторінки під час внутрішньої прокрутки. Перевірено 2
колонки на 1024 px, 1 колонку на 390/320 px, пошуковий фокус, cancel/confirm та
збереження після перезавантаження. Скриншоти шести станів генеруються у
`docs/evidence/meal-plans/day-editor-{1440,390,320}-{light,dark}.png` і додаються
до артефактів Targeted workflow.

## Інкрементальна перевірка

`DAY_ONLY=1` явно включає PG та concurrency, тому непридатний для повторів після CSS
або browser-only змін. Новий `DAY_BROWSER_ONLY=1` залишає disposable DB, міграції
й синтетичні fixtures, але запускає лише Chromium. Повні PG/concurrency suites
не повторювалися після незмінних server/domain залежностей; їхній попередній локальний
прогін пройшов: 66 тестів, 1175 assertions, усі day/writer/selector/structure/week
deletion/repetition/publication concurrency сценарії. Обов'язковий Targeted PR gate
виконує вибраний набір на точному head SHA.
