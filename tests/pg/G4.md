## Запуск у Linux Cloud

Потрібні Bash 4+, стандартні утиліти Linux, локальний Docker daemon через Unix
socket і PHP з `pdo_pgsql` у тому самому середовищі, де виконується агент.
Не використовуйте віддалений Docker daemon, публічний порт, privileged-контейнер,
host network або монтування Docker socket у PostgreSQL. Якщо штатний дозвіл
Docker/мережі недоступний, зупиніться й зафіксуйте блокер.

З кореня репозиторію:

```bash
bash tests/pg/run-isolated-pg.sh
```

Скрипт спочатку перевіряє інструменти, потім завантажує офіційний
`postgres:18-bookworm`. Це **тег для пошуку актуального образу**, а не зафіксована
точна версія. Перед створенням контейнера скрипт отримує repository digest та
image ID; контейнер запускає саме за цим незмінним ID. Журнал містить digest,
`SELECT version()`, `server_version_num`, `/etc/os-release`, версію `btree_gist`,
кодування та ICU locale БД. Перевірка вимагає major 18.

Після першого успішного прогону запишіть фактичну точну версію та digest у звіт
і повторюйте запуск з відповідним pin (підставте перевірені значення):

```bash
PG_TEST_IMAGE='postgres:18.X-bookworm@sha256:ACTUAL_DIGEST' bash tests/pg/run-isolated-pg.sh
```

`18.X` та `ACTUAL_DIGEST` — позначення для заміни, не готова команда.
У цьому PR жодна точна версія/digest образу не підтверджені фактичним запуском;
історичний PG 18.6 з аудиту не є доказом версії Docker-образу.

## Що готує ізольований запуск

- Новий контейнер, нову внутрішню Docker-мережу та tmpfs `/var/lib/postgresql`;
  постійні volumes, локальні дані й секрети не монтуються.
- Єдиний опублікований порт: `127.0.0.1:<випадковий>:5432`. Він потрібний PHP/PDO
  поза контейнером; psql виконується через `docker exec`. PDO завжди підключається
  до loopback, а не до IP контейнера. Якщо це заблоковано політикою Cloud,
  скрипт завершується помилкою, без обходу мережевих обмежень.
- Нову `telmanfit_test`, власник `postgres`, UTF8, ICU `uk-UA`, `template0`.
  Перед SQL-модулями перевіряється відсутність таблиць у `public`.
- `telmanfit_test_runner`: LOGIN, NOSUPERUSER, NOCREATEDB, NOCREATEROLE,
  NOREPLICATION, NOBYPASSRLS; CONNECT/TEMPORARY на тестову БД та USAGE/CREATE
  на `public`. Немає CREATE ON DATABASE. Створені runner таблиці/функції належать
  йому; це дозволяє перевіряти DDL без адміністративних прав.
- `btree_gist` встановлює адміністратор у новій БД до модулів. Версія розширення
  виводиться і повторно перевіряється раннером.
- HBA дозволяє адміністратору лише локальний socket, а runner — лише
  `telmanfit_test` з SCRAM. Інші з'єднання відхиляються. Це HBA виключно нового
  контейнера. Паролі генеруються випадково для прогону, не друкуються і не
  комітяться; bootstrap env-файл має права 600 та видаляється після старту.
- Модулі `docs/01→04` застосовуються рівно один раз до нової БД від runner.
  Повторний запуск скрипта створює інший контейнер з порожнім сховищем.
- Після SQL-тестів `check-pdo.php` через PHP-драйвер Laravel перевіряє
  `current_database`, `current_user`, `session_user`. Застосунок Laravel не
  завантажується, `.env` не читається, міграції не запускаються. Це перевірка
  транспортного підключення PDO, а не Laravel Feature-тест або перевірка ORM.

EXIT/INT/TERM запускає очищення тільки збережених ID власного контейнера й мережі.
Контейнер видаляється разом із tmpfs, env-файл прибирається. Образ лишається
у Docker cache; чужі ресурси не очищуються. Помилка видалення дає ненульовий
код виходу. Після SIGKILL/аварії daemon автоматичне очищення не гарантоване:
перевірте ID з журналу, не використовуйте загальний prune.

## Самостійний Bash-раннер

Раннер не готує схему. Для вже підготовленої **окремої тестової** БД:

```bash
# PGPASSWORD або ~/.pgpass задаються поза репозиторієм.
PG_TEST_PORT=5433 bash tests/pg/run-pg-tests.sh

# Або psql усередині власного тестового контейнера:
PG_TEST_CONTAINER=OWN_TEST_CONTAINER bash tests/pg/run-pg-tests.sh
```

Імена БД/ролі фіксовані: `telmanfit_test` / `telmanfit_test_runner`; хост —
`127.0.0.1`. У кожному psql-з'єднанні до тестового SQL перевіряються поточна БД,
`current_user`, `session_user` та відсутність привілейованих атрибутів ролі.
`psql -X -w -v ON_ERROR_STOP=1`; SQL-помилка перериває прогін.

Успіх вимагає всіх точних назв `t01→t06`, рівно шести файлів і кожного ID
рівно один раз зі статусом PASS: T1.0–T1.8 (9), T2.1–T2.16 (16),
T3.1–T3.24 (24), T4.1–T4.12 (12), T5.1–T5.15 (15).
Підсумки також мають збігтися: **PASS=76 FAIL=0 GAP=0**; у t06 немає сценаріїв.
Пропуск, дубль, зайвий ID, FAIL, GAP або відсутній підсумок відхиляються.
До тестів і після кожного файла виконується автоматична перевірка: рівно 37
таблиць та жодного рядка в бізнес-таблицях. Дані не очищуються. Зміни identity
sequences від `nextval` не відкочуються й не вважаються залишками даних.

Коди виходу: 0 — повний успіх; 1 — інша помилка; 2 — з'єднання/ідентичність/
привілейована роль; 3 — схема/розширення; 4 — SQL-помилка тесту; 5 — неповний
набір чи неправильні результати; 6 — інвентаризація/залишки даних.
Окремі приватні журнали кожного прогону: `tests/pg/out/run.*/` (gitignored).

**Обмеження:** це еталонна схема з SQL, рівно 37 бізнес-таблиць. Майбутні
Laravel-службові таблиці не можна підтримати просто збільшенням ліміту:
потрібні окремий перелік бізнес-таблиць, інвентаризація й перевірка залишків.
G3/R1 з BIGINT `users.id`, FK та значеннями понад 2147483647 потребує окремих
тестів; чинні `_ids.val integer` і ці 76 сценаріїв цього не доводять.

## Фактичні перевірки цієї підготовки

- Git Bash: синтаксис трьох `.sh`; контрактний `bash tests/pg/test-runner.sh` —
  10 випадків успішно: повний набір, відмова ідентичності, пропуск ID, дубль ID,
  GAP, FAIL, відсутній підсумок, SQL-помилка t06, залишки рядків, відсутній файл.
  Використовується підставний psql; жодна БД не викликається.
- `php -l tests/pg/check-pdo.php` — успіх; `git diff --check` — успіх.
- Docker image/digest/версія: **не перевірено**, образ не завантажено.
- Контейнер, роль, БД, застосування модулів: **не виконано**.
- Фактичні PG PASS/FAIL/GAP: **невідомі, 76 сценаріїв не запускалися**.
- PDO connectivity: **не перевірено**.
- Тимчасових Docker-ресурсів не створено; видаляти нічого, чужі ресурси не зачіпалися.
